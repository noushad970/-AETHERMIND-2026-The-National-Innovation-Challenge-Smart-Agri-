# Offline Disease Detection Model

The AI Agriculture Assistant ships a TensorFlow Lite crop-disease model
that runs entirely on the device for **Android, iOS, macOS, Windows, and
Linux**. On **Flutter Web** (and any other platform where `dart:ffi`
is unavailable) the app transparently falls back to the Gemini cloud
model.

This document covers:

1. The model architecture and training setup.
2. One-time conversion from the trained Keras model to `.tflite`.
3. How the Flutter app wires the model into the UI.
4. Why the conditional-import trick is needed for web.
5. Day-to-day troubleshooting.

---

## 1. Model

- **Architecture**: EfficientNetB0 backbone + a small classification head,
  trained on the PlantVillage subset covering **28 crop-disease classes**
  across **Corn, Potato, Rice, and Wheat**.
- **Input**: `224 × 224` RGB float32 tensor, pixel range `[0, 255]`
  (no rescaling layer — the model bakes the normalisation in).
- **Output**: 28-class softmax.
- **Class list**: [`assets/models/labels.json`](../assets/models/labels.json)
  is generated by the conversion script and shipped with the app.
  The Dart-side lookup table at
  [`lib/data/services/disease_info.dart`](../lib/data/services/disease_info.dart)
  maps every raw class to a full agricultural record (causes,
  prevention, treatment, organic and chemical solutions).

## 2. One-time conversion

You only need to convert once, after you have a trained Keras model
(`best_model.keras` or your equivalent). The conversion script lives
at [`AI Model/scripts/convert_to_tflite.py`](../AI%20Model/scripts/convert_to_tflite.py)
and runs on plain CPU Python — no extra dependencies beyond TensorFlow.

```pwsh
cd "c:\Users\user\Desktop\BD Apps Smart Agri system\AI Model"
& C:/Users/user/AppData/Local/Programs/Python/Python313/python.exe scripts/convert_to_tflite.py
```

The script:

1. Loads `best_model.keras`.
2. Calls `tf.lite.TFLiteConverter.from_keras_model()` with default
   (float32) optimisation — this keeps accuracy identical to the
   Keras model.
3. Writes:
   - `assets/models/disease_model.tflite`
   - `assets/models/labels.json`
4. Runs a sanity check: feeds one batch of validation images through
   the TFLite interpreter and prints the top-1 prediction.

The model + labels are tracked in `assets/models/`. There is a
placeholder `README.md` in that folder so the directory exists in
fresh checkouts and the `flutter:` asset registration in
[`pubspec.yaml`](../pubspec.yaml) does not warn.

## 3. Running the app

```pwsh
flutter pub get
flutter run            # picks up the connected Android/iOS device
flutter run -d macos   # or any desktop device
flutter run -d edge    # Gemini cloud fallback is used automatically
```

During startup the app initializes the TFLite classifier in
[`DiseaseDetectionProvider`](../lib/features/ai_disease/presentation/providers/disease_detection_provider.dart).
The classifier is loaded asynchronously; the first `detect()` call
waits for it to finish before running inference. The result screen
shows a small badge indicating either the **offline** model or the
**cloud** model was used for the prediction.

## 4. Why the conditional import is needed

`package:tflite_flutter` ships `dart:ffi` bindings into the TFLite C
runtime. `dart:ffi` is not available on Flutter Web, so importing the
package at the top of a file would break the entire web build.

The fix is in [`lib/data/services/disease_classifier.dart`](../lib/data/services/disease_classifier.dart):

```dart
import 'disease_classifier_stub.dart'
    if (dart.library.io) 'disease_classifier_native.dart';
```

- On Android/iOS/macOS/Windows/Linux, `dart:io` is in scope, so the
  `..._native.dart` file is compiled in. It contains the real
  `tflite_flutter` calls.
- On Flutter Web, `dart:io` is absent, so the `..._stub.dart` file is
  compiled in. The stub reports `isAvailable = false` and the
  provider falls back to Gemini.

Both files expose the same `buildDiseaseClassifierImpl()` factory, so
the rest of the app is unaware of which one is in use.

## 5. Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `UnimplementedError: TFLite is not supported on this platform` | You hit the stub path on a real device. | Re-run on Android/iOS/desktop (not `flutter run -d chrome`). |
| All predictions return `class_$i` | `labels.json` is missing or its format is wrong. | Re-run the conversion script and confirm the file is non-empty. |
| Every prediction has confidence near uniform | The model weights file is corrupted. | Delete `disease_model.tflite` and re-run the conversion script. |
| Build fails on web with `dart:ffi is not available` | A new file accidentally imported `tflite_flutter` directly. | Move the import behind a conditional import (see§4). |
| The badge says "Cloud" even on Android | The runtime didn't load the .tflite asset. | Check `pubspec.yaml` has `assets/models/` listed and the file is present. |

## 6. Where to look in the code

- `lib/data/services/disease_classifier.dart` — public API + conditional-import switch.
- `lib/data/services/disease_classifier_native.dart` — Android/iOS/desktop implementation.
- `lib/data/services/disease_classifier_stub.dart` — Web/no-`dart:io` stub.
- `lib/data/services/disease_info.dart` — 28-entry agricultural knowledge base.
- `lib/features/ai_disease/presentation/providers/disease_detection_provider.dart` — orchestrates offline → cloud fallback.
- `lib/features/ai_disease/presentation/screens/disease_detect_screen.dart` — the UI with the model-source badge.
- `AI Model/scripts/convert_to_tflite.py` — Keras → TFLite conversion script.
- `assets/models/disease_model.tflite` and `labels.json` — generated artifacts (replace by re-running the script).
